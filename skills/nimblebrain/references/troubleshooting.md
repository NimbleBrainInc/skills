# Troubleshooting

Find the error, give the answer's `fix`, and stop. The rule about the model key holds
while diagnosing: never print or open the files that hold it.

`npx nimblebrain help --json` lists every error code with its default fix. This table
adds the cause and what to do beyond that fix; a code missing here needs nothing more.

| `error`, or symptom | Cause | Fix |
|---|---|---|
| `DOCKER_MISSING` | Docker is not installed. | The person installs Docker Desktop or Docker Engine from `https://docs.docker.com/get-docker/`, then you run `doctor` again. |
| `DOCKER_NOT_RUNNING` | Docker is installed but not running. | The person starts Docker Desktop (or the Docker service). Run `doctor` again once it is up. |
| `DOCKER_PERMISSION` | On Linux, this user is usually not in the `docker` group. | The person follows `https://docs.docker.com/engine/install/linux-postinstall/` and signs in again. Do not run Docker as root for them. |
| `ARCH_UNSUPPORTED` | The runtime publishes no image for this CPU. | Say so and stop. Do not force another platform: under emulation the runtime crashes. |
| `LOW_MEMORY` | Docker has less memory than the runtime needs (about 2 GB). | The person raises Docker's memory in its settings, then you run `init` again. |
| `PORT_IN_USE` | The port named with `--port`, or a resumed install's recorded port, is taken; or no free port was found after 27246 (a new install moves past a taken default on its own from CLI 0.9.0). | Run `status`: if this install is already running, there is nothing to do. Otherwise the person stops the other process, or you pass another `--port` on their say-so. |
| `PORT_IN_USE` for the agent worker's port, from `update`, `up` or `use` | Another program holds the subscription worker's port after this install's own worker let go of it. The install is left as it was. | Give the answer's `fix`: the person stops what holds the port, then you run `npx nimblebrain up --json`; or, on their say-so, `npx nimblebrain use claude --port <port> --json` (`use codex` on Codex) gives the worker a free port. |
| `NOT_INSTALLED` | There is no install in the CLI's home (`~/.nimblebrain-local`, or `NIMBLEBRAIN_HOME`). | Run `npx nimblebrain` to install it, or pass the `--home` the install uses. |
| `USAGE` | An unknown command, flag or flag value, or `update --runtime` naming an older release (exit 2). | Check `npx nimblebrain --help` and fix the command. |
| `START_FAILED` | Compose could not start the runtime; `message` is its last error line. | Run `logs --json`, report the last error line as written, then run the command again once it is addressed. After a failed first install, that command is `npx nimblebrain`, which finishes the same install. |
| `NEEDS_TERMINAL` | `key` was run with no terminal attached. | The person runs `npx nimblebrain key` in their own terminal. Never pass the key yourself. |
| `CANCELLED` | The person declined, or `uninstall` ran without `--yes` under `--json` or with no terminal. Nothing changed. | If the person said yes, run `npx nimblebrain uninstall --yes --json`; otherwise stop. |
| `NOT_OURS` | The home folder holds files the CLI did not write, so installing there could overwrite them and `uninstall` would delete them. | Report it and stop. Never remove files the CLI did not write. For a second install, use another `--home`. |
| `INSTALL_INCOMPLETE` | The install's first start never finished (`status` shows `phase: "starting"`). | Run `logs --json` to find why, then `npx nimblebrain` to finish it, or `uninstall` on the person's own yes. |
| `MODEL_KEY_MISSING` | `use api` with no key stored and no terminal to ask at; or, from a CLI before 0.7.0, `init` with no key (a newer `init` succeeds without one). | The person runs `npx nimblebrain key` in their own terminal, then you run the command again; or choose another source with `use`. |
| `AGENT_CLI_MISSING` | `use claude` or `use codex`, and Claude Code or Codex is not installed. | The person installs it from the `fix` and signs in to their subscription with it; then run `use` again. |
| `AGENT_NOT_SIGNED_IN` | The agent's CLI is not signed in. | The person signs it in themselves (`claude`, then `/login`; or `codex login`), then you run `use` again. Never handle their login. |
| `AGENT_BILLS_API_KEY` | The agent's CLI is signed in with an API key, which would bill API pricing, not the subscription. | The person signs it in to their subscription instead (the `fix` names how), then you run `use` again. |
| `PLATFORM_UNSUPPORTED`, `HOST_LOOPBACK_UNREACHABLE` | `use claude` or `use codex` off macOS. On Linux the container reaches this machine over the Docker bridge, not `127.0.0.1`. | Say so; use an API key (`npx nimblebrain key`) or a local model instead. |
| `AGENT_WORKER_FAILED` | The agent worker stopped before it answered; the answer's `log` is `agent-worker.log`. | Read the last lines of that log and report them as written; usually the agent's CLI was signed out or removed. After the person fixes that, run `use` (or `up`) again. |
| `RUNTIME_UNSUPPORTED` from `use` | The installed runtime is too old to run on a subscription. | Run `npx nimblebrain update --json` (on a pre-release, with `--runtime`), then `use` again. Data survives the update. |
| `NOT_RUNNING` | `open`, `telemetry on`/`off` or an `mcp` command was run while the runtime is stopped. | Run `npx nimblebrain up --json`, then the command again. |
| `UPDATE_REQUIRED` | `mcp add` on an install from before runtime `v0.76.0`, which cannot reach this machine. | Run `npx nimblebrain update --json`, then `mcp add` again. Data survives the update. |
| `URL_NOT_LOOPBACK`, `URL_INVALID` | The URL is not an `http(s)` URL on `localhost`, `127.0.0.1` or `::1`. | Use the server's loopback URL, such as `http://127.0.0.1:8000/mcp`. |
| `NAME_TAKEN`, `NAME_IS_CATALOG_ENTRY`, `INVALID_SERVER_NAME` | The name is in use in the workspace, belongs to a catalog connector, or is empty or reserved once lowercased with other characters turned into hyphens. | Pass another `--name`; for `NAME_TAKEN`, `mcp list` shows what holds it. |
| `WORKSPACE_NOT_FOUND` | `--workspace` names no workspace. | Pick one from the answer's `workspaces` (or `status --json`) and pass it with `--workspace`. |
| `SERVER_NOT_FOUND` | `mcp remove` names no server in the workspace. | Run `npx nimblebrain mcp list --json` for the names, then remove by one of them. |
| `DIRECT_URL_NOT_ALLOWED` | The instance is not a local install made by `npx nimblebrain`, so it adds servers only from its catalog. | Run `npx nimblebrain update --json`, or add the server to the instance's connector catalog. |
| `REQUEST_FAILED` | The runtime refused the request for another reason; `message` carries its text. | Run `logs --json`, report the last error line as written, then run the command again once it is addressed. |
| `mcp add` succeeds with a `warning`, or the server shows as not running | The server was not running when it was added, or it listens where Docker cannot reach it. | Start the server; on Linux it must listen on the bridge address or `0.0.0.0`. Then reconnect it from the Connectors page. |
| `TELEMETRY_LOCKED` | `DO_NOT_TRACK` is set, or this install has nowhere to send data. | Nothing to do: telemetry stays off. Tell the person if they asked to turn it on. |
| `LOCAL_MODEL_UNREACHABLE` | Ollama does not answer on `127.0.0.1:11434`: it is not installed, the person declined starting it, or it did not answer within 30 seconds of a start. | Give the error's `fix`, which names the step for this machine (`brew install ollama`, the download page, opening the app, or `sudo systemctl start ollama`); never install Ollama yourself. Then run the same command again. From `up`, NimbleBrain is already running; only its own agents wait on Ollama. |
| `LOCAL_MODEL_MISSING` | The model is not on Ollama: the download was declined, failed, or ran out of disk. | With the person's yes, run `npx nimblebrain local-model --yes --json` again, or `ollama pull <model>` first. |
| `LOCAL_MODEL_NO_TOOLS` | The model cannot call tools. | Use a model with tool calling, such as `gemma4:e4b`. |
| `LOCAL_CONTEXT_SMALL` | `doctor` found the model's context window below 32k, so long prompts would be cut. | Run `npx nimblebrain local-model --yes --json` again. |
| `INTERRUPTED` | The CLI was stopped (a signal, Ctrl-C, a killed session) before it answered. | Run `npx nimblebrain status --json` to see what is in place, then run the same command again; `init` is safe to repeat. |
| `HEALTH_TIMEOUT` | The runtime is still starting, or it exited. | Run `logs --json` and report the last error line as written. Then run the command again; after a failed first install, `npx nimblebrain` finishes it. |
| Chat shows an error | The key is wrong, expired, out of credit, or for another provider. | The person runs `npx nimblebrain key` again. |
| Chat says Claude Code (or Codex) isn't answering, or the composer shows "isn't running" | On a subscription, the agent worker is stopped. | Run `npx nimblebrain up --json`; it starts the worker again. |
| Chat says Claude Code is signed out, or its plan's limit is reached | The agent's CLI lost its sign-in, or the subscription's usage limit is reached (the message gives the reset time when the CLI does). | The person signs the CLI in again (`claude /login` or `codex login`), or waits for the reset, or switches with `use api` or `use local` on their say-so. |
| A turn is slow, or chat shows "Waiting for Claude Code to start answering" | On a subscription, every turn writes a `timeline` line to `agent-worker.log` in the install's folder: seconds from start for `init`, `request`, `message_start`, the first text, `result` and `exit`, then any `retry` events and the plan's `rate_limit` status. | Read that turn's line. A gap before `request` is the agent's CLI starting up; one between `request` and `message_start` with no retries is the provider being slow; `retry … overloaded` means it retried. Report what the line shows; it holds no prompt or answer text. |
| The agent connects, then fails with `-32022` or "unsupported protocol version" | The agent's MCP client is older than the revision the runtime serves. Codex's client does not speak that revision yet, so Codex connected as a coding agent gets no NimbleBrain tools; running NimbleBrain's own agents on Codex (`use codex`) is not affected. | Update the agent; for Codex, use another coding agent to reach NimbleBrain's tools for now. |
| The agent cannot see NimbleBrain's tools right after `init` | The agent loads MCP servers when a session starts. | The person opens a new session. |
